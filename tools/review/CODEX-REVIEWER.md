# Weblate translation review rules

Repeatable checklist for the second-model review in ut-docs#4366 and
ADR-0160 §4.

## Inputs and scope

- Weblate API base: `https://translate.universaltill.com`; project:
  `universal-till`.
- Read the credential from `WEBLATE_AUTH` in the environment. Never print,
  persist, log, commit, or comment with its value.
- Review languages in order: `fr`, `ms`, `zh_Hans`; later, any language
  with pending work.
- Components: `sale`, `catalog`, `orders`, `reports`, `staff`, `settings`,
  `tills`, `setup`, `selforder`, `receipts-and-legal`, `plugins`, `support`,
  `common`.

## Read, then judge

For each language and component, page through pending suggestion units:

```text
GET /api/translations/universal-till/C/L/units/?q=has:suggestion AND NOT label:legal
```

Later, inspect AI text saved as translations but not approved:

```text
GET /api/translations/universal-till/C/L/units/?q=state:translated AND NOT label:legal
```

For each unit, read its English `source`, `explanation`, `flags`, `context`,
and suggestions from `GET /api/units/{id}/suggestions/`. Load the project
glossary once per language from component `glossary` and apply its terms.

Judge every candidate against all of these requirements:

1. Meaning matches the English in the context described by the explanation
   for a till/POS UI used by cashiers or managers.
2. Every placeholder, HTML tag, and ICU construct has identical syntax and
   count (`%s`, `%[1]d`, `{name}`, `{{.X}}`, `<b>`, and similar).
3. `max-length` is respected; otherwise keep close to the English length.
4. Use the correct register and terminology: German `Sie`; Turkish `siz`;
   French `vous` and French non-breaking spacing before `: ; ! ?`; Spanish
   usted (Spain); European Portuguese; Bahasa Malaysia, not Indonesian;
   mainland Simplified Chinese with full-width punctuation; Arabic and Farsi
   are formal and right-to-left. The glossary takes precedence.
5. Use the correct script. Chinese, Arabic, and Farsi must not contain Latin
   leftovers except brand/technical terms: Universal Till, Bluetooth, Wi-Fi,
   PIN, USB, QR.
6. Add no explanations, quotes, notes, or untranslated English.

## Actions

- Good: `POST /api/suggestions/{sid}/accept/` with `{"approve": true}`.
  If a unit has multiple suggestions, accept the best and delete the others
  with `DELETE /api/suggestions/{other}/`.
- Bad: delete the suggestion and post a one-line reason to
  `POST /api/units/{id}/comments/` with scope `translation`.
- A reviewer may submit a better version as a new suggestion using
  `POST /api/units/{id}/suggestions/`, but must never approve text they wrote.
  A human or another model must approve it (ADR-0160 §4).
- Unsure: leave the suggestion untouched and include it in the report.

## Hard rules

- Never touch units labelled `legal`; receipt, tax, and fiscal wording is
  human-only.
- Never change English/source strings, component settings, add-ons, or
  machinery.
- Never approve any text with a placeholder mismatch, regardless of wording.
- Pause about 0.2 seconds between write calls; back off on HTTP 429.
- Log every action (unit id, key, action, reason) to
  `.review-logs/<date>-<lang>.jsonl`. Logs are gitignored and must never
  contain the token.

## Report

When a language is complete, comment on universaltill/ut-docs#4366 with a
short table per component: approved, rejected, left for human, and legal
skipped. Include the five most common rejection reasons and any systematic
translator issue that should be corrected in the Ollama instructions. End
the comment with `_Generated by Codex_`. Do not move the card's Status.
